## 4. Pre-TestFlight command sequence (the exact thing to run)

The dispatch asked for the literal command sequence Chau runs before each TestFlight archive. Reconciled against `feedback_cap_sync_ios_mechanics` (worktree pitfall) and `feedback_ios_info_plist_stability` (do not touch `Info.plist` unless adding a new permission):

```bash
# 0. From the main worktree (or a fresh /tmp worktree with isolated npm ci —
#    NOT a symlinked node_modules, per memory rule cap_sync_ios_mechanics).
git fetch origin
git checkout main
git pull --ff-only

# 1. Lockfile-faithful install.
npm ci --legacy-peer-deps

# 2. Build the web shell into dist/ (this is what cap sync copies into the iOS bundle).
npm run build

# 3. Sync the dist/ output + Capacitor config + Pod updates into ios/.
npx cap sync ios

# 4. Verify nothing unexpected changed. The Podfile.lock and the iOS public/
#    snapshot are tracked even though ios/ is gitignored as a directory.
git status   # expect: Podfile.lock and possibly ios/App/App/public/* updated
git diff -- ios/App/Podfile.lock

# 5. Bump the iOS build number for TestFlight.
#    Open ios/App/App.xcodeproj/project.pbxproj OR use Xcode UI:
#       Project → App target → General → Build = 17  (was 16)
#    Bump MARKETING_VERSION only if the user-visible version is changing.

# 6. Open the workspace (always the .xcworkspace, never the .xcodeproj alone).
npx cap open ios

# 7. In Xcode:
#    a. Select "Any iOS Device (arm64)" as the run destination.
#    b. Product → Archive.
#    c. Wait for the archive to appear in the Organizer.
#    d. Distribute App → App Store Connect → Upload → follow prompts.
```

**Gotchas baked in to the workflow:**
- Step 0 must use a `git`-clean worktree. `cap sync ios` writes into `ios/App/App/public/` and updates `Podfile.lock`; running it on a dirty branch mixes the sync's automatic edits with your in-progress work.
- Step 2 must succeed before step 3. `cap sync ios` does not build for you; if `dist/` is stale, you ship stale JS. (`scripts/check-bundle-budget.mjs` from #809 now enforces the build's eager-bundle ceiling in CI, but locally you still need to remember to build.)
- Step 5: increment `CURRENT_PROJECT_VERSION`, not `MARKETING_VERSION`, for a normal TestFlight build. App Store Connect rejects archives that re-use a build number that has been uploaded before.

## 5. Pre-store-submission blockers (do not ship without these)

Three open PRs are material to the next store submission. None of them blocks a `cap sync` or an Xcode Archive — they block the **review/policy** side.

### #796 — `fix(privacy): guard marketing trackers against native execution (per A41)` — OPEN
- Native builds currently can still fire Pixel/GA4/UTM trackers because the privacy gate only runs in the web shell. App Store / Play submission with unsanctioned ad SDK behavior is a policy risk (App Tracking Transparency, Play Data Safety).
- **Must merge + device-verify on a TestFlight build** before submission so reviewers don't see surprise network calls.

### #821 — `feat(native): iOS dSYM upload script + Xcode Run Script docs (Sentry gap #1)` — OPEN
- Verified locally: `grep -n "dSYM\|sentry-cli upload-dif" ios/App/App.xcodeproj/project.pbxproj` returns **zero hits**. The Xcode Run Script that uploads dSYMs after an Archive is not wired in.
- Without this, every TestFlight crash is **obfuscated frames only** in Sentry — `<UIWindowSceneManager>` instead of the file/line. Adds significant ops debt on every iOS issue from this build forward.
- **Should land before submission** so the first store-submitted build is symbolicated.

### #811 — `fix(privacy): add 42 missing user-id tables to delete-account manifest (B1 follow-up to #797)` — OPEN
- GDPR/CCPA right-to-erasure compliance: the delete-account flow currently misses 42 tables; a deleted user's rows persist in those tables.
- Web users hit this today too. App store submission elevates the risk because account-deletion-in-app is required for App Store / Play.
- **Should land before submission** so the right-to-erasure claim is honest.
