# C3.3 Defect Brief — Speak Follow-Up Retry Loop And Observability Gap

Date: 2026-07-11

## Symptom

Two consecutive clear spoken answers were rejected with the "didn't catch that" / repeat prompt.

## Impact

Learner answers clearly but is pushed into a loop that looks like speech recognition failure. This blocks speaking practice and hides whether the failing component is STT clarity, DeepSeek follow-up generation, API auth, or provider failure.

## Suspected Area

`src/pages/AiTutor.tsx` collapses null follow-up results into `SPEAK_TRANSCRIPT_ASK_TO_REPEAT_TEXT`. The DeepSeek follow-up path is also a knowingly under-observed path: provider failures can look like learner speech failure unless surfaced as typed provider errors and logged.

## Notes

Do not fix in this pass beyond the C3.3 auth/API state distinction. A follow-up workpack should add structured client/server telemetry for speak-follow-up result class: auth failure, provider failure, timeout, invalid model question, validation rejection, and transcript clarity rejection.
