## 1. Audio generation pipeline

**Script:** `scripts/generate-spanish-audio.ts` (added in #432, "Google Cloud TTS for Spanish").

- **TTS service:** Google Cloud Text-to-Speech, REST `v1/text:synthesize`.
- **Voices:** `es-US-Neural2-A` (female), `es-US-Neural2-B` (male) — LatAm-leaning Neural2. Sentences alternate F/M by index; vocab = female; dialogue A=F / B=M.
- **Source of truth:** the Supabase `public.lessons` table (`language='spanish'`, `level='b2'`), **not** the local `lessons-b2.ts`. The local `.ts` is synced to Supabase by `scripts/sync-lessons-to-supabase.ts` (workflow `sync-lessons.yml`); B2 content (#436) is already in Supabase — confirmed by the dry-run loading 25 rows.
- **Output path:** `b2/es/l{slug}/{unit}_{N}[_A|B].mp3` in the public `room-audio` bucket. Slug = lesson id with `spanish_` prefix stripped. This **exactly matches** what the resolver looks for (`lessonAudioBase` in `src/lib/lessonAudio.ts`), so generated files immediately stop the 404s.
- **Idempotent:** checks `existsInBucket` per key before generating; re-runs only fill gaps. `--force` re-renders. Safe to run/re-run.
- **Fails loud:** no silent ElevenLabs fallback; transient network errors return null and are logged per-clip without killing the batch.

**Why B2 is silent:** not a casing/path bug. The sync script writes `level` lowercased (`extractLevel` → `.toLowerCase()`), the generator queries `.eq("level","b2")`, and the dry-run matched all 25 rows — the query is correct. A1/A2/B1/C1/C2 audio was generated by past runs of this same script; **the `--level=b2` run was simply never executed.** Operational gap, exactly as the brief hypothesized.
