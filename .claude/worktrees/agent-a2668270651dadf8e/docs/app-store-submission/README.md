# App Store / Play Store submission kit

Single home for everything Chau needs to submit MercyBlade to the iOS App Store and Google Play.

> **Read first:** `reports/app-store-submission-package-2026-04-26.md` is the source-of-truth copy bank — app names, subtitles, descriptions, keywords, age-rating answers, screenshot shot list, SDK disclosure table, demo-account guidance, rejection-risk audit. The checklists in this folder reference it; they don't replace it.

## What's in this folder

| File | What it's for |
|---|---|
| `ios-submission-checklist.md` | iPhone + iPad — App Store Connect required fields, with status (complete / pending / blocked) per item. |
| `android-submission-checklist.md` | Google Play Console required fields, same format. |
| `descriptions/vi.md` | Vietnamese description, char-counted. |
| `descriptions/en.md` | English description, char-counted. |
| `whats-new/v1.0.0.md` | Per-version changelog template ("What's New in this version"). Copy + bump for each release. |
| `aso-strategy.md` | Keyword research, ELSA / Cake competitor benchmarks, Vietnam vs US conversion targets. |

## What's NOT in this folder (intentionally)

- **Demo reviewer account migration.** A6's submission package §5 explicitly recommends *not* committing a reviewer-user migration to git: "DO NOT auto-create; do it from the admin panel." Reasons: passwords would land in git history; the account state should be tied to a real review cycle and rotated; an auto-seeded user can drift from prod schema. The iOS / Android checklists below have a "create demo account" step that points to A6's §5 guidance.
- **Screenshots themselves.** Generated by `scripts/generate-screenshots.ts`. Capture day-of-submission so they reflect current UI.
- **Bundle-ID alignment decision.** A6 §0 flagged the iOS (`com.chaudoan.mercyblade`) vs Android (`com.mercyapps.mercyblade`) divergence. Decide before first submission — this kit assumes the existing values.

## Submission day workflow

1. Run `scripts/build-for-submission.sh ios` → produces an IPA ready for App Store Connect.
2. Run `scripts/build-for-submission.sh android` → produces an AAB ready for Play Console.
3. Run `scripts/generate-screenshots.ts` against staging.
4. Walk the iOS checklist top-to-bottom; flip every "pending" to "complete" or "blocked".
5. Same for Android.
6. Paste descriptions from `descriptions/{vi,en}.md`.
7. Paste this version's `whats-new/v*.md` into "What's New in this version".
8. Submit.

## Linking from the web app

The legal URLs that Apple and Google require live in the app:

- Privacy Policy: `https://mercyblade.com/privacy` (existing) and `https://mercyblade.com/legal/privacy` (alias added by this PR).
- Content Advisory: `https://mercyblade.com/legal/content-advisory` (added by this PR).
- Terms of Use: `https://mercyblade.com/terms` (existing).

Both stores prefer stable URLs that don't change with each release — the `/privacy` and `/terms` paths are the long-lived ones. The `/legal/*` paths are added so the same content fits the structured submission paperwork.
