## Hard reminders for the next session

- **Search before assuming the answer.** Two real artifacts in this session (`!74`, `!84`+`!90` for RLS audit) were in memory but not in `git log` — always verify with `git log --all --oneline | grep` or `find` before treating memory as truth.
- **Verify "doc doesn't exist" with `git show origin/main:<path>` or `git ls-tree -r origin/main` after `git fetch origin` — not `find` against a possibly-stale local checkout.** Lesson from 2026-05-27: Fixer reported `rls-audit-surface.md` missing; it had been on main since `b1d0b26cf` (!84). The authoritative check is the remote ref, not the working tree.
- **Same lesson applied twice on 2026-05-27:** `disaster-recovery.md` was also assumed missing per Fixer's find output and turned out to be a 1040-line runbook on main. Always verify with `git ls-tree -r origin/main` after `git fetch origin` before authoring or replacing any doc.
- **Squash-merging the base of a stacked PR chain can orphan children.** Verify post-merge with `git log origin/main -- <changed-file>` for critical CI/deploy changes. The merge button can lie (confirmed twice).
- **Destructive SQL on prod requires per-op approval.** Reads via service-role are fine. INSERT/UPDATE/DELETE/DDL are not, regardless of agent confidence.
- **Don't re-dispatch the "39KB eager leak" / mercy-guide re-dispatch.** Closed by PR #636. Bytes are shared-app-core, not mercy-guide.
- **`searchRooms calculateScore()` has an unconditional `+0.5` for `hasData`.** Flagged in !716/!716 equivalent. Do not "fix" without an explicit ranking-policy decision.
- **Apply the learner-tomorrow test** before every brief: "If this succeeds, what does a Vietnamese learner, Chau, or the deployed app do tomorrow that they cannot do today?" If unanswerable, the work is theater.
- **Order of operations on RLS-tightening migrations:** deploy client code using the new auth path FIRST, verify in prod, THEN apply REVOKE. Reversed order breaks production for the deploy window.
