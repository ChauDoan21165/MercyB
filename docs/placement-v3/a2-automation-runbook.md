# A2 Placement V3 Observability Automation Runbook

Placement V3 remains disabled while this automation runs.

Required flag state:

```bash
PLACEMENT_TEST_ENABLED=false
PLACEMENT_V3_UI_ENABLED=false
VITE_PLACEMENT_TEST_ENABLED=false
VITE_PLACEMENT_V3_UI_ENABLED=false
```

## Local Simulation Mode

Use this mode for routine A2 validation:

```bash
npm run placement:a2:validate
npm run placement:a2:evidence
```

The validation script runs the local failure-injection harness, replays each `after` scenario, checks forensic log integrity, writes a dashboard summary artifact, checks retention-policy prerequisites, and checks rollback-readiness prerequisites.

Evidence generated by this mode must be treated as:

```text
simulated=true
live_provider_validated=false
supabase_persistence_validated=false
placement_v3_enabled=false
```

Artifacts are written under `reports/placement-v3/a2-observability/<run-id>/`, and `reports/placement-v3/a2-observability/latest` points at the latest run.

## CI Mode

The scheduled workflow `.github/workflows/a2-observability-simulation.yml` runs with Placement flags explicitly set to false. It executes:

```bash
npm run placement:a2:validate
npm run placement:a2:evidence
```

CI uploads the generated report directory as an artifact. CI mode does not call live providers and does not write to Supabase.

## Live Validation Mode

Live validation is intentionally separate from this automation. Do not mark live validation complete unless real credentials and deployed infrastructure are used.

Before claiming live provider validation:

- Use real provider credentials in an approved staging or production validation window.
- Save redacted provider logs and matching forensic rows.
- Confirm provider metadata, retry/fallback behavior, and latency are from a real provider call.

Before claiming Supabase persistence validation:

- Write forensic events to a live Supabase project.
- Read back `placement_v3_forensic_events`, `placement_v3_failure_timelines`, and `placement_v3_runtime_alerts` evidence.
- Confirm dashboard rows are backed by persisted rows, not fixtures.

Until those checks are complete, reports must keep:

```text
live_provider_validated=false
supabase_persistence_validated=false
```

## Manual Checks

Retention prerequisites:

```bash
npm run placement:a2:retention
```

Rollback prerequisites:

```bash
npm run placement:a2:rollback
```

These scripts verify that the required policy/runbook and migration prerequisites exist. They do not prove live retention enforcement or live rollback execution.
